# Player website and wiki: the pages

The website docs: `website.md` (how the site is built: hosting, sources, the generator, the catalogue, guides and changelog data), `website-pages.md` (what each page shows and does). How to update and publish it: `docs/dev/publishing-guide.md`.

## Every page
- **Header:** one row at the top, then the tabs. On the row: at the left the mod's icon (its panel's, `hs-panel-icon.png`, also the browser tab's icon) and "Hypersynergism Guide for v<version>" (colour-cycling), halfway between the edge and where the original site centred them (the icon scaled smoothly, not pixelated); in the middle five counters (features, categories, settings, "Live Channel" or "All Channels" on the changelog, "QoL + opt-in AutoSing"), at their own width, centred on the tabs under them (not spread to the tabs' width); at the right the credit line. Below 1320 px wide, where one row no longer fits with the counters centred, the counters take their own line above the other two (the original site's layout). Six tabs: Home orange, Features green, Wiki cyan, Changelog plum, GitHub light blue, About white. The current tab is filled with its colour and a line of that colour runs under the tabs. No fixed height: the game's header keeps room for a third row, which left an empty band above the tabs (not kept: long pages need the room). Footer: source, credits, back to top.
- **The mod's icon opens a quick access menu**, like the mod's icon in the game: the guides in category order, each with its category's icon (from `GUIDES`: a new guide joins it), then, below a line, Help & bug reports. CSS only (`guide.css`), so it works without JavaScript: shown at once while the icon or the menu is hovered, closing 200 ms after the mouse leaves (the game's delays; not a delay before opening: the game has none). The focus keeps it open only from the keyboard (`:focus-visible`) or on a touch screen (`hover: none`; the icon is a button that leads nowhere, so a tap opens the menu instead of leaving the page): a mouse click on the icon doesn't pin it open. Not the Discord thread: Help sends players there first and says what to bring.
- **The counters lead to what they show:** Features → the features page, Categories → the wiki index, Settings → the settings page, Live Channel → the Installation & updates wiki page's "Live and Dev channels" entry (unlinked on the changelog, where it reads "All Channels"), QoL + opt-in AutoSing → the Auto-Sing guide; the version → its changelog entry (Live's first), else the changelog's top (a Dev version often has none yet). Their look is unchanged; hovering underlines the label.
- **Links leaving the site open in a new tab and get a small grey icon** after them: GitHub's mark, Discord's, or a generic "opens elsewhere" arrow (`guide.css`, by address). The site is read beside the game, and the icon is the warning WCAG asks for; screen readers hear "(opens in a new tab)" (the icon's alternative text). `page()` adds `target="_blank"` to every link to another site, so no catalogue entry, guide or changelog writes it; the site's own full addresses (`SITE`) stay in the tab. No icon in the changelog's entries (each has several GitHub links); the screen-reader text stays.
- **Accessibility (WCAG 2.2 AA, checked with axe-core):** text keeps 4.5:1 against its background, so two game colours are a little brighter on the site: the Features tab's green (`#009400`, the selected tab's dark text) and the Settings counter's red (`#ff2020`). A link among text has a faint underline (its blue is under the 3:1 asked against the text around it); lists made only of links, titles and setting chips have none. Headings skip no level: a wiki page's feature titles are `h2` under its `h1`, drawn like the features page's `h3`.
- **A link's target that has no highlight of its own** (a guide heading, the home page's Help) flashes a pale yellow background on arrival (2.5 s, held while the page scrolls; none under reduced motion or without JavaScript), also when the address already pointed to it: `guide.js` sets a class, since `:target` alone can't replay an animation. A feature, a changelog entry and a settings row keep their own highlight.
- **Screenshots enlarge over the page** on a click (`guide.js`, a `<dialog>`): one file pixel per screen pixel, the largest sharp size, shrunk to the window; a click anywhere, Close or Esc closes it, "Open the file" opens it in a tab (for a tall one shrunk to the window). Without JavaScript, or with a modifier key, the link opens the file. On the features page a miniature still unfolds its entry instead.
- **Inline code** uses a monospace font list at 0.94 em: a bare `monospace` is drawn smaller still by browsers (13 px for 16 px text).
- **The content is a column centred in the window** (at most 1200 px, footer included, paragraphs at most 112 characters wide), its text left-aligned; the header spans the whole width, like the game's.
- **Each page has its own `<meta name="description">`** (search results, link previews): a line passed to `page()`, the general sentence on the home page; a wiki category page lists its category and as many feature titles as fit in 160 characters, so it never goes stale.
- **Maintainers are named by their GitHub names** (Ferlieloi, maenhiir); the About page and the catalogue's "Live and Dev channels" entry add the other names players know (XxmolkxX, Shewchou).
- **Every page works without JavaScript**: everything is shown, only search and folding need it.
- **Narrow screens** (640 px and less): the page scrolls as a whole, the header with it (wider, only the content scrolls under a fixed header); side margins drop, the category lists (home, wiki index) take one column, the settings table shows one labelled block per setting. **Reduced motion** stops the version's colour cycle and every transition. **Printing** leaves out the header, the search forms and the footer.
- **Keyboard:** a "Skip to content" link, a yellow outline on the focused control, the current tab marked `aria-current`; counts of shown entries are announced (`aria-live`).
- **The About page promises** no analytics, cookies, account system or save uploads: whatever is added keeps it true.
- **Filters are kept in the address** (`?q=`, `?category=` or `?channel=`) so a filtered page can be shared, except on a page opened as a file.

## Home, GitHub, About
- **Home:** an introduction, quick links (features, wiki, the installation guide, releases, help), the categories with their feature counts (each linking to its wiki page), four first steps for new players (the installation guide, where the mod's icon is…), Help & bug reports (`#help`), the original project.
- **Help & bug reports is the site's one help text:** Discord first (the thread, and the server's invite since the thread opens only to members), then GitHub issues; what to send with a bug (what happened, the mod's version from the panel's title, a backup file, private); first things to try, CLEAR SETTINGS last. The wiki index's Help points to it.
- **GitHub:** GitHub's logo as its heading (in the site's text colour on the page's background: `docs/res/github.png` is the dark logo recoloured, its transparency kept), then the links grouped by what a visitor wants, each saying what it leads to: get the mod (the latest Live release from the changelog, the installation guide, releases), bugs and requests (issues, Help & bug reports), source (Live, Dev, the channels entry), contributing (the developer docs), related (ahvonenj's original repository, the game's source). **About:** maintainers, the original website's style, privacy, licence.

## Features page (`features.html`, `guide.js`)
- **Each entry shows its title and summary**; "How to use it & limits" opens the rest: where, details, availability and limits, related settings (by the label the Settings tab shows, a hidden setting by its description without its trailing note in parentheses; each links to its row on the settings page, the key as its tooltip), its own source files if any. The entry's title links to itself.
- **Skimmed by title:** a title is bold and white, its summary a softer off-white right under it, the category's intro (with its guide link) light grey-lilac at full size behind one unbroken rule in the category's colour, "How to use it & limits" smaller still; a 2 px line separates entries. Not a fold on each title: title + summary is what a reader skims, the details toggle is enough.
- **A click anywhere on an entry opens or closes its details** (`guide.js`), except on a link or a control and except when it ends a text selection.
- **An entry's state shows as a background and a left bar** (drawn inside the box: nothing moves): hovered with a mouse, a lighter background and a grey bar; open, a lighter one still and a lilac bar; open as the link's target, a yellow bar. A closed entry has none, the link's target included. Lilac, not the category's colour: Input and Golden Quarks are gold, too close to the target's yellow.
- **Clicking a title** opens its entry where it is, without scrolling (it is in view), and puts its link in the address bar, which turns its bar yellow; on an open entry it closes it. A link from anywhere else brings the entry to the top (next rules).
- **Search** matches every word typed against the whole text of an entry (details included), punctuation and symbols ignored on both sides, so a setting's label typed as the panel shows it ("Repeat hover (hold left Shift)", "S216+") finds its entry; **Category** shows one category. A category with no match is hidden.
- **Categories start folded.** The script turns each category title into a toggle (`<button aria-expanded>` inside the `<h2>`, a triangle on its left that turns in place) followed by the number of features in grey (the number of matches during a search). A folded category shows only its title. Not `<details>` in the generator: the heading would lose its heading role for screen readers, and the filter would have to open them anyway.
- **No full list for a frame first:** a script in the page's head sets `html.folding`, which hides every category's contents (titles shown, the triangle's room kept) until `guide.js` has folded them. Lifted by `guide.js` whatever happens (`finally`), by the script tag's `onerror` if the file fails to load, and after 5 s in any case: an error never leaves the features hidden. Without it, the list showed unfolded for 1–2 frames (20–45 ms) on most loads, on any network.
- **Fold all / Unfold all** next to Reset acts on the categories shown; its label says what a click does and its width doesn't change with it.
- **A search or a category choice unfolds everything**, folds included that the address brought in at load; once both are cleared, the folds from before come back. Folds made during the search are dropped then.
- **Folds are not remembered** across visits: a returning visitor seeing empty categories would think features were missing.
- **A link to a feature** (`#<feature id>`) clears a filter that hides it, unfolds its category, opens its details and scrolls to it.
- **Printing shows every category in full**, folded or not, without the triangles.
- Limits: the browser's find (Ctrl+F) doesn't search folded categories (`hidden="until-found"` would clash with the `hidden` the filter sets).

## Wiki pages (`docs/wiki/`)
- **Index:** the categories, the guides (in category order, so the installation guide first, each with its category's icon), the references (settings, calculations, `FEATURES.md` as a file), a Help line pointing to the home page's Help (Discord thread, issues, developer docs). No link to the GitHub Wiki: it only points back here.
- **Category page:** its intro, its guide, a table of contents, then every feature in full (no folding, nothing to open), with the same anchors as the features page.
- **Settings:** the top of the mod panel's Settings tab (`settings-tab`, cropped from the `mod-panel` shot) floats right of the intro, no taller than its text, so every table keeps the column's width (not the section titles beside it: a table opened beside the image stayed that narrow, its lines broken in two; not an image shrinking when a section unfolds: the table would move after the click); not one screenshot per tab: the table already shows each page's settings in order, a shot would show a save's values next to the defaults and go stale at each settings change. Then the Settings tab's pages as the tab shows them (page order, then group order from `hs-settings-control-pages.json` and `hs-settings-control-groups.json`, then `hs-settings.json` order, like the panel), a table per page with a row per group; then "Saved choices and internal state", the hidden settings grouped by their feature's category. A row, anchored by its key: the `settingDescription` (not the help text: the row links to its feature), a platform note when `platforms` limits it, the key in grey under it, the default (`settingValue`, else `enabled`: On or Off for a switch, a dash for a button or an empty choice), its feature. Not the control type or page: the sections say it. **The sections fold like the features page's categories** (`guide.js`, `makeFoldable()` shared by both): all folded at load, a triangle and the section's number of settings in grey on each title, Fold all / Unfold all above the first, no flash of the unfolded page (`html.folding`), every section printed in full. A link to a setting unfolds its section and brings the row to the middle of the screen (its group and column titles stay in view).
- **Calculations:** the calculation picker's entries (`toolingSupport: true`), sorted by name, with their function and whether they support reduction. Read by pattern from the TypeScript file (`website.md`, "How the generator is organised": when the run stops).
- **`FEATURES.md`:** every category and feature in one Markdown file; its settings and guides link to the website (address built from the catalogue's `repository`). **`FEATURE-AUDIT.md`:** counts and each category's sources, under the original audit's fixed text.

## Changelog page (`changelog.html`, `changelog.js`)
- **Display:** every entry, newest first (date, then version, then channel). Versions sort as the release helper's `compareVersions` does: digits as numbers (2.10 after 2.9, dev10 after dev9), a suffix after its base (2.14.5, then 2.14.5-dev1). A card: the version (linked to its GitHub release if any), a channel badge (Original, Live, Dev version, Loader), the date and, for a version record, "Historical build" (a source labelled "Build containing …") or "Source version"; contributors; merge notices; changes grouped Added / Changed / Removed / Fixed; notes; sources, folded.
- **Contributors:** each linked to its profile; "(release)" or "(version record)" for a release-only credit, "(merged)" for the merger.
- **A catch-up** shows "Dev → Live" or "Live → Dev" and "Includes changes from" linking to the incoming versions' cards ("(partial)" when only part came in); its own changes then come under "Changes from Live" (or Dev). Searching a change of an incoming version also finds the catch-up that brought it.
- **Filters:** Channel and a search over version, contributors and their aliases, changes and notes (every word must match); Clear resets both. A link to an entry (`#<entry id>`, or an old id kept in its `aliases`) clears a filter that hides it.
