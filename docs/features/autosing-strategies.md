# Autosing strategies: format, conversions, default strategies

The autosing docs: `autosing.md` (the run), `autosing-strategies.md` (strategy format, conversions, default strategies), `autosing-editor.md` (strategy and actions windows). Players' guide: `docs/data/guides/autosing.md` (published to the website and wiki by `scripts/tools/build-docs.py`), updated with any change players see.

A strategy is JSON: phases (each from a start stage to an end stage, with its steps) plus an AOAG phase. Defaults live in `resource/json/strategies/`; validation and conversions are in `hs-strategy-manager.ts`.

**The last phase is "singularity → end"**, the one autosing runs after AOAG (`finalPhaseProblem`, checked at save and import, not by `validateStrategy`). No stage before AOAG falls in it (the game's last one before is `omega-singularity`), while a wider final phase would also run before AOAG as an end phase, which AOAG doesn't stop. Older stored strategies that end otherwise still load and run as before (autosing's final phase is the one that ends at "end"); not converted: a migration duplicating the final phase's steps on both sides of "singularity" wasn't worth it for the few strategies concerned.

Saving or deleting changes the in-memory strategy list only after localStorage accepts the write. A failed write keeps the previous list and reports failure; a failed editor save keeps its draft open.

`validateStrategy` checks untrusted structure before migration and returns a normalized copy: recognized actions, finite nonnegative timings/completions, corruption options, and valid IF conditions and destinations. Import, save, stored-data load and Autosing start use it; the execution loop does no validation. Invalid stored entries are logged and skipped without rewriting them on disk. A load writes the list back when a migration changed a strategy, unless an entry was skipped (`docs/dev/compat-code.md`). IF destinations use zero-based indices, including the action count for end of phase; backward jumps remain valid. Older IF steps without a mode normalize to `challenges`, as in the editor. Fractional completion targets and signed IF comparisons/exponents remain valid.

## IF steps
- **Modes** (`ifJumpMode`): `challenges` (a challenge's completions vs a value), `stored_c15` (C15 vs the stored score × 10^x), `aoag` (the Antiquities rune bought or not, `ifJumpAoagBought`; validation refuses anything but a boolean and doesn't check the operator, which the editor writes as ">").
- **AOAG mode reads the live player's `runeLevels[6]`** (the game's own test), synchronous after "Click AOAG" (901): the game buys at once, no dialog. Without it (bookmarklet; a Steam game from before the rune rework, which kept the level outside the player) the IF never jumps, with one warning per run. Not read from a captured save: the level comes from the EXP through `levelsPerOOM`, which the Ambrosia loadout changes. 901 itself warns when the live player shows the rune still not bought after its click (silent where it can't be read). Test: `test-strategy-validation.cjs`.
- **An IF reads its condition at most once per game tick (5 ms) in a pass** (`#IF_RECHECK_MS`): checked again sooner, it sleeps the rest first. A loop whose steps never wait on a timer or the game (an IF jumping to itself with Wait before 0; loadout switches, 403 "next ascension", 405, 156–158, 215, a challenge whose target is already met) ran in microtasks only: the game never ticked, the condition couldn't change and the page froze, Stop included; Max jumps ran out in microseconds. A loop that waits elsewhere (Wait before ≥ 5 ms, completions, game cycles: all the default strategies' loops) never sleeps there. Not a wait on every IF, nor a minimum Wait before: the first cost every IF a timer, the second didn't cover stored and imported strategies.
- **Max jumps** (`ifJump.ifJumpMaxJumps`, optional): after that many jumps in one phase pass the IF goes on to the next step even when its condition holds; absent or 0 = no limit. Counted per IF (its index in the running list) from the start of each pass (`#executePhase`), not per singularity. A false condition doesn't count. Validation refuses anything but a whole number ≥ 0. The editor writes it only when > 0, so an old IF updated with ✎ stays unchanged.
- Reaching it writes a normal log line (`Step N - IF … : max jumps (5) reached, no jump`), not a debug line; no notification (a low-stat account hits it at every singularity). During a run the log keeps only warnings and errors unless the full log is on (`autosing.md`), so it shows only then; not let through that cut-off (not wanted). Test: `test-autosing-corruption.cjs`.

## Corruption steps
- **A level is set only by "Set corruption level" (403)**, the level in the step's `corruptionLevel` (an actual level: the game adds the free levels, `autosing.md`). Phases have no level.
- **"Ascend immediately"** (`ascendAfterCorruption`): a strategy without the field gets `true` when loaded, and validation refuses a 403 step without a boolean. The step list shows "(ascend now)" or "(next ascension)" after the level. Test: `scripts/tests/test-autosing-corruption-editor.cjs`.
- **"Cleanse corruption" (405)**: `cleanseToHighest` optional; validation refuses anything but a boolean. The editor always writes it. The step list shows "(to 0)" or "(to highest cleared)". 405 is the first free id: 400–402 and 404 still name removed actions in the conversions.
- **No named corruption loadouts** (a level is one number, nothing to name).
- **Removed actions**: 400 "Corrup 0*" (one corruption action less), 401 "Corruption level from phase (reapply)" (with the phase levels), 402 "Corrup Ants", 404 "Set corruption level minus free levels" (set the lowest level that reached the target once free levels were added; removed for 403's actual level). The `corruptionFreeLevels` patch went with 404 (`#RETIRED_PATCHES`, older installs still report it); GDS's `calculateFreeCorruptionLevels()` stays (Tools tab, effective level).

## Game toggle steps
- **"Set Auto Challenge / Ant-Sac / Ascend" (156–158)** set the game's toggle to the step's ON/OFF (`toggleOn`, absent: ON; validation refuses anything but a boolean; the editor always writes it; the step list shows "(ON)" or "(OFF)"). The game's buttons only flip, so the step clicks only when the state differs, read from the live player, else from a fresh save (never the button's text). Already in that state: nothing done. With the live player, a click the game didn't take is a warning. Test: `test-strategy-validation.cjs`.
- **The flip actions 153–155** ("Auto Challenge / Ant-Sac / Ascend Toggle") still run in older strategies, but the editor's dropdown no longer offers them (hidden `<option>`, shown when such a step is loaded): the game keeps these toggles through a singularity, so one flip per singularity alternated ON and OFF. Not converted to 156–158: a flip's result depends on the state at that moment. 153 keeps its old behaviour, exiting the Transcension and Reincarnation challenges after its click (players' strategies may rely on it); 156 doesn't exit. No default strategy uses 153–155: Quark Molker and TAS follow each of their 156 steps with 101 and 102, 153's behaviour with a known end state (an exit outside a challenge does nothing).

## Conversions (`ensureAoagPhase`, `normalizeCorruptions`)
Older formats are brought to the current one at load of the player's saved strategies, at import and at save, silently unless noted:
- A phase's level → a 403 step at the phase's start (later if-jumps +1), except in the first and AOAG phases (dropped: they ran at 0).
- No `formatVersion` (before 2, autosing set level 0 and reset before the AOAG phase) → the AOAG phase gets that as its first step, a 403 at 0 that ascends at once, commented with why (`AOAG_LEVEL_STEP_COMMENT`: no offering penalty at 0; a replaced 103's own comment wins) (`ensureAoagPhase`). It replaces a leading 103 (which did nothing after that reset) unless an IF jumps to it, else is inserted (if-jumps +1). Once only: `formatVersion` 2 records it, so a removed or changed step stays so. A strategy with no AOAG phase gets the default one, which already starts with it. The editor keeps the strategy's `formatVersion`.
- 401 → a 403 at its phase's level (removed when the phase had none).
- 404 → a 403 with the same number (now an actual level: a higher effective level than before).
- 400 → a 403 at level 0.
- A phase naming a corruption loadout (`corruptionLoadoutName`) gets its level, "None" an empty level.
- A "Load Corruption Loadout" step (202, `loadoutName`) → a 403 step with that level, the loadout's name as comment when it had none (removed when the loadout doesn't exist: it did nothing). `corruptionLoadouts` is dropped.
- Strategies from before the game's 4.4.0 (8-value `corruptions` / `loadout` objects, 402 steps): levels at 0 (no conversion of 8 values into a level), 402 steps removed with later if-jumps moved up one step, saved back, one warning.

## Default strategies
- **Strategies sent by their author** (Demon King (rus) v2.0 and v2.1) are bundled as sent (only `strategyName` set to the file name), steps and levels included; the notes below are about the others, which Shewchou converted after the game's 4.4.0 corruption rework.
- **Corruption levels** (a simple base for their authors to tune): the first phase starts at 0 (`autosing.md`), the AOAG phase with a 403 at 0 (its leading 103 became it; same comment as the conversion's). Only two level steps: 20 right before the "Exit Ascension challenge" (103) that leaves the first C15 (so the next ascension gives hepteracts), and 50 as the first step of singularity → end.
- **The C15 loop of the last phase** (`IF C15 < 1e110` jumping back) has max jumps 5 in Demon King (BTMco), Quark Factory and Quark Molker: low-stat accounts stayed in it forever. Not TAS (its `C15 < 1e15` loop is in phase 2).
- **"-temp" suffix** on the converted ones' names, file names included (players shouldn't expect them to run well yet); not on a strategy its author sent. The dropdown lists the "-temp" ones in their own "Not Yet Retuned" group (`isNotRetunedDefaultStrategy`): a version sent by its author, without the suffix, goes back to "Default Strategies".
- **Previous versions stay bundled** when an author sends a new one, so players can go back to them: the new file is added next to the old one. The dropdown lists a default strategy under "Previous Versions" when another default has the same name before " v" and a higher version (`previousVersionNames`, numeric parts: v1.10 > v1.9). Group order: Default Strategies, Previous Versions, Not Yet Retuned, User Strategies. Previous Versions and Not Yet Retuned are grey (secondary choices); the other two white. A default can't be deleted: the Delete button is greyed while one is selected, with that as its tooltip, and still clickable (the click says why).
- **A default strategy is known by its file name**: a player who had one selected keeps it when a newer version arrives (now under "Previous Versions"; the changelog tells them to select the new one). Renaming or removing a file makes them fall back to the first in the list.
- **Every phase resets somewhere** (checked when phase passes stopped ascending, `autosing.md`). The converted default phases have no phase-start Ascend.
